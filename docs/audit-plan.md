# 框架核验与测试目录整理

目标：复核当前未提交改动，修复可复现的问题，集中测试并完成提交和 push。

1. 核对基线：Go 版本、完整 race 回归、真实 MySQL/Redis 集成测试、生成器构建验收。
2. 请求绑定：通过回归测试检查 JSON 尾部、大小限制和同名内部字段；修复已复现问题。
3. 代码生成器与公共工具：检查非自增主键（含 0）、SQL 默认值、字段重名、哈希碰撞下的节点移除；补回归测试。
4. 将全部 `*_test.go` 移入 `test/cases/`，保持原包目录结构。用 Go 原生 overlay 在原包上下文执行，保留私有函数测试与相对路径语义；不在生产代码中增加测试接口。
5. 增加统一运行入口及文档；生成器副本验收必须使用统一入口，避免空跑。
6. 最终运行构建、race、集成、覆盖率、fuzz、vet、staticcheck、gosec、govulncheck、凭证扫描，记录实际结果与限制。
7. 检查最终 diff，提交，普通 push 到 origin/main，不强制推送。

审查重点：外部输入能否越过绑定边界；生成代码能否编译及正常写入；低权重节点遇到哈希碰撞是否破坏其他节点；测试集中后是否被漏跑；集成 skip 与实际通过是否明确区分。
